Connect to Microsoft Fabric

Sign in with a Microsoft Entra ID service principal (app registration) that has access to your Fabric tenant. Its three values come from the Azure portal → Microsoft Entra ID → App registrations → your app.

Copy the secret's Value from Certificates & secrets — it is shown once, at creation. Two things must also be true in the tenant, or the call returns an empty list: a Fabric admin has enabled Admin portal → Tenant settings → Service principals can use Fabric APIs for a group the app belongs to, and the app has been added to each workspace as Admin, Member or Contributor. Nothing is stored — the values are used for this session only.

The destination is recorded with the run and written into the audit report. This browser client generates the .pbip / .pbit for you to download — it does not publish to the workspace on your behalf.

Autonomous Agents Architectural Summary

Technical breakdown of the 4 autonomous migration engine phases implemented in cli/ai_qvf_to_powerbi.py and cli/qvf_extractor.py.

Phase 1 · Extract

1. Assessment — extract

Job: Get facts out of the source file. Read-only reverse-engineering of .qvf binary.
Implemented in cli/qvf_extractor.py

A .qvf is an opaque Qlik binary archive. This phase reverse-engineers it in 7 steps: reads file header, scans binary for zlib-compressed streams, decompresses and classifies each as JSON, then extracts:

  • Load Script: How Qlik sourced its data
  • Data Model: Fields, tables, and data types
  • Sheet Inventory: Visual chart objects, dimensions, and measure expressions
  • App Metadata: App properties and variables
Fallback Recovery: If the data-model stream is unreadable, it recovers field names from the load script, then raw binary regions. Emits [WARN] and reports gaps rather than inventing them.
Phase 2 · Model

2. Parsing — model

Job: Turn source data structure into target's semantic model (model.bim).
Implemented in UniversalModelGenerator (ai_qvf_to_powerbi.py:382)

Compiles model.bim (Power BI's tabular model definition). Tables and field lists come from the load script; column types come from .qvf metadata via TypeResolver.

  • DAX Translation: Line 563 calls multi-tiered AI brain per Qlik expression
  • Type Resolution: Explicit validation from source metadata
  • Power Query M: Builds partition source definitions
Zero-Guessing Policy: "Nothing here fabricates rows or infers a type from a column name." Unresolvable expressions are parked with -- TODO: translate this Qlik expression manually stubs rather than a plausible-looking wrong answer.
Phase 3 · Report

3. Mapping — report

Job: Rebuild the visual reporting layer — what the end-user sees.
Implemented in UniversalVisualGenerator (ai_qvf_to_powerbi.py:586)

Translates each Qlik chart into its Power BI equivalent via explicit visual lookup mapping:

barchart → clusteredColumnChart linechart → lineChart piechart → pieChart kpi → card sn-table → tableEx filterpane → slicer gauge → card treemap → treemap

Writes page.json / visual.json per sheet, binding visuals to Phase 2 model columns/measures and laying out canvas coordinates. Chart-level expressions pass through AI brain (line 680).

Fidelity Loss Note: gauge and kpi collapse to card; distributionplot and combochart collapse to clusteredColumnChart. Power BI has no exact equivalent, so fidelity is intentionally handled via safe native visual mappings.
Phase 4 · Package

4. Report Generation — package

Job: Assemble deliverables and account for overall migration results.
Implemented in UniversalPBIPGenerator (ai_qvf_to_powerbi.py:732)

Writes project scaffolding (.pbip, definition.pbir, definition.pbism, version.json) and compiles deliverables:

  • .pbit Template: Schema-only template (opens directly)
  • _PBIP.zip Bundle: Full Microsoft Fabric Power BI Project
  • MIGRATION_AUDIT_REPORT.md: Complete audit record (:1072)
Pipeline Trustworthiness: The audit report records self.ai.unresolved — every expression the AI couldn't translate confidently. This forms your manual review queue, telling you what it didn't manage rather than silently shipping guesses!
